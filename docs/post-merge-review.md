## What transferred from Devanity

Studied [usedevanity/skills at 6a1ac85](https://github.com/usedevanity/skills/tree/6a1ac85db635da8de52e2ce37f384c0b1647ace0): README/kernel, quality/basis-form, architecture/audit/improve procedures, adjudication and reported ablation. The useful transfer is ownership by meaning, a failure-reproducing check before a behavioral fix, and enforcement near an existing boundary. These are applied to Research's scientific contracts, not used to import a second governing framework.

- One owner per procedure: supervised action/role handoff lives in the existing supervision reference; skills and phases route to it. Mechanical schema shapes remain runtime-owned. The read-only reviewer returns judgment; the orchestrator persists it.
- One predicate per invariant: committed mutation remains detectable after restoration, through the same `git_integrity` predicate for typed records and legacy RUN/EXEC/ASMT.
- Structural guidance becomes an existing-suite check: operational instruction pointers resolve in the installed plugin; lower-level primitives cannot import orchestration.

No Devanity hooks, dependency, authority ledger, automatic approval ritual or alternate scientific state machine was installed. Its small-sample coding ablations are not evidence that these changes improve scientific impact or agent research quality. The transfer is justified by local defects and checks below.

## Verification and cost

Local checks: 79 tests pass on Python 3.12, runtime compilation passes, plugin/marketplace JSON parses, and `git diff --check` passes. The full suite includes separate-process provenance/replay/graph reconstruction and supervised release inspection. CI retains the existing Python 3.10/3.12 matrix.

The final local suite took about 12 seconds, versus about 8 seconds for the preceding 63-test implementation run; the different test sets prevent attributing that difference to runtime performance. The shared history check adds Git history queries to legacy immutable-record validation, proportional to record/history size. Graph additions are proportional to declared edges. There is no new runtime dependency, persistent state, execution phase, external hook or CI job. This is an observed regression-free improvement in the tested envelope, not a universal Pareto/performance guarantee.

Instruction duplication was replaced with routing and one operational role contract. The new short AGENTS file serves plugin maintenance, with existing commands and boundaries; it is not a second research workflow. No agent benchmark has established a token-cost or task-success gain from those instruction changes.

This is a system-level review with targeted runtime probes, not a new formal proof of every statistical method or every code path.

The core can verify exact declared bytes, ordering, coverage and witnesses. It cannot establish that all material assertions in prose were found, that a reviewer has expertise, that an agent followed an instruction outside the cooperative CLI, or that unrecorded external exposure did not occur. Native host interception, independently authenticated reviewer launch, scientific efficacy and measured real-user UX remain unverified. The next evidence for those claims is a representative end-to-end agent evaluation with disclosed host instrumentation and a baseline comparison; adding more prose or folders would not supply it.

The immutable-history check is intentionally conservative: a committed rewrite is rejected even when later restored. Corrections must use a new identity. Large-history optimization is warranted when measured validation cost becomes material; it must preserve the same mutation-detection contract.
