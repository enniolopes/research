# Scientific model

## Two coupled loops

Research combines a permissive **discovery loop** with a restrictive **confirmation/control loop**.

### Discovery

```text
observe
 -> update model
 -> find gap/anomaly
 -> generate rival explanations
 -> seek evidence
 -> compare
 -> select discriminating test
 -> repeat
```

Discovery may use analogies, mechanisms, speculative branches, literature contradictions and unexpected results. Most exploratory thoughts should never become durable graph nodes.

### Confirmation/control

```text
hypothesis
 -> commit
 -> freeze consequential choices
 -> execute
 -> inspect checks
 -> test null/rival explanations
 -> inference
 -> claim
 -> independent challenge
```

A post-result idea may enter exploration, a prospective specification, deferred work or a reopened design. It may not silently rewrite confirmatory history.

## Evidence-first behavior

For material questions, prefer the operation that can establish the fact:

- literature proposition -> search, retrieve and read;
- data proposition -> inspect and compute;
- code proposition -> inspect or execute;
- robustness proposition -> run the sensitivity/null test;
- novelty proposition -> conduct scoped precedent search;
- scientific claim -> trace result + design + checks + inference.

## Result and claim distinction

A result is an executed or externally identified observation. A claim is an interpretation licensed by design and checks.

```text
result + design + assumptions/checks -> inference/warrant -> claim
```

The system must preserve the possibility that a correct numeric result licenses only a weak claim.

## Null-first reaction to interesting results

Before explaining an attractive anomaly, attempt to make it disappear through applicable alternatives such as implementation error, data leakage, measurement artifact, denominator choice, selection, confounding, temporal trend, multiple testing, random variation and known precedent.

## Claim types

The system may eventually distinguish claim classes when different evidence standards are required, for example observation, association, estimate, mechanism, causality, generalization and novelty. Do not add this taxonomy to runtime until an evaluation demonstrates that the distinction prevents a real failure.

## Next-best test

The orchestrator should prefer tests that discriminate among live explanations and reduce important uncertainty. Formal expected-value-of-information is optional; the operational principle is not.

A useful test considers relevance, discriminating power, expected information gain, cost, feasibility and scientific consequence.
